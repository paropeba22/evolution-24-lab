# Channels V1 P3 lab overlay

This repository overlays `evoapicloud/evolution-api:homolog`; it is not an upstream source fork. The image inspected for this patch was the Linux amd64 manifest `sha256:65e29aa1a2ca096675825ff8feb3b5bf7fbcb167e368f9282fd80670e8da18a2`, whose OCI revision label is `e273b904d53f5726970fd6a244ed9caa61dfeb9a`. The Dockerfile keeps the `homolog` tag. Both patch scripts require unique exact bundle patterns and fail the build if mutable `homolog` no longer matches. Revalidate the tag's image digest before building or deploying; P3 does not deploy.

The direct Chatwoot API Inbox route validates `X-Chatwoot-Timestamp` (Unix seconds), `X-Chatwoot-Signature` (`sha256=` HMAC-SHA256 over `<timestamp>.<raw JSON>`), and `X-Chatwoot-Delivery` before invoking `receiveWebhook`. It fetches the intended API Inbox's `secret` over HTTPS using the configured Chatwoot administrator token, requires exactly one matching Inbox name, and compares signed payload account/Inbox IDs. A bounded five-minute in-memory delivery cache rejects replay on one process. Cross-process replay during the signature window remains possible without shared replay storage.

The compiled Chatwoot service is wrapped with Node `AsyncLocalStorage`; its existing `provider` property is scoped to the current asynchronous call, so concurrent instances cannot overwrite one another's token/account/Inbox context. Outbound send errors now propagate as HTTP failure instead of a caught HTTP 200. No automatic WhatsApp resend is introduced after an ambiguous result. Private notes and `WAID:` echo prevention remain in the original service path.

For NEXI-bound local webhooks, `NEXI_CHANNELS_EVENT_MASTER_SECRET` must match NEXI's secret and be at least 32 bytes. Evolution exposes an instance-specific HMAC key check through the protected `webhook/find` API so NEXI can prove both servers use the same key. Evolution derives a per-instance HMAC key and signs `<millisecond timestamp>.<instance name>.<instance ID>.<exact JSON body>` with SHA-256 in `X-Nexi-Event-Signature`. NEXI-bound QR payloads are reduced to a pairing state signal before signing; QR, pairing code, and global API key are not forwarded. Event logging and terminal QR logging are redacted. The original reconnect/session policy, including 408 handling, is unchanged.

`node --test nexi-transport.test.cjs` exercises authentication, replay, instance isolation, and event signing. The bundle patch was also applied to the exact image layer's `dist/main.js` and checked with `node --check`; no Docker runtime is available in the local execution environment.
