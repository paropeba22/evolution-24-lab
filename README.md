# Channels V1 P3 lab overlay

This repository overlays `evoapicloud/evolution-api:homolog`; it is not an upstream source fork. The image inspected for this patch was the Linux amd64 manifest `sha256:65e29aa1a2ca096675825ff8feb3b5bf7fbcb167e368f9282fd80670e8da18a2`, whose OCI revision label is `e273b904d53f5726970fd6a244ed9caa61dfeb9a`. The Dockerfile keeps the `homolog` tag. Both patch scripts require unique exact bundle patterns and fail the build if mutable `homolog` no longer matches. Revalidate the tag's image digest before building or deploying; P3 does not deploy.

The direct Chatwoot API Inbox route validates `X-Chatwoot-Timestamp` (Unix seconds), `X-Chatwoot-Delivery` (UUID), and `X-Chatwoot-Signature` (`sha256=` HMAC-SHA256 over `<timestamp>.<delivery UUID>.<exact raw JSON>`). It fetches the intended API Inbox's `secret` over HTTPS using the configured Chatwoot administrator token, resolves the exact configured `inboxId` for NEXI instances, and compares signed payload account/Inbox IDs. Changing only the delivery UUID invalidates the signature.

Direct Chatwoot dispatch requires Evolution's existing shared Redis configuration (`CACHE_REDIS_ENABLED=true`, `CACHE_REDIS_URI`, and a shared `CACHE_REDIS_PREFIX_KEY`). An atomic `SET NX EX` claim, keyed by an opaque hash of instance/account/Inbox/delivery UUID, runs before `receiveWebhook`. The delivery remains reserved after a crash or uncertain send; completed and ambiguous deliveries receive an idempotent HTTP 200 without another WhatsApp action. A first-attempt send failure still returns HTTP failure. Claims expire after 30 days, well beyond the five-minute signature acceptance window. Redis must be shared by every replica. Runtime `CONFIG GET` requires `maxmemory-policy=noeviction`, `appendonly=yes`, and `appendfsync=always`; missing privileges, a mismatched policy, or an unavailable store produce HTTP 503 before dispatch. **DIRECT CHATWOOT TRANSPORT REQUIRES SHARED REPLAY STORE.** No Redis was installed or configured by this source correction.

The compiled Chatwoot service is wrapped with Node `AsyncLocalStorage`; its existing `provider` property is scoped to the current asynchronous call, so concurrent instances cannot overwrite one another's token/account/Inbox context. Outbound send errors now propagate as HTTP failure instead of a caught HTTP 200. No automatic WhatsApp resend is introduced after an ambiguous result. Private notes and `WAID:` echo prevention remain in the original service path.

For NEXI-bound local webhooks, `NEXI_CHANNELS_EVENT_MASTER_SECRET` must match NEXI's secret and be at least 32 bytes. Evolution exposes an instance-specific HMAC key check through the protected `webhook/find` API so NEXI can prove both servers use the same key. Evolution creates a UUID once for each emission, reuses its prepared headers/body on that emission's HTTP retries, and signs `<millisecond timestamp>.<event UUID>.<instance name>.<instance ID>.<exact JSON body>` with SHA-256 in `X-Nexi-Event-Signature`. NEXI-bound QR payloads are reduced to a pairing state signal before signing; QR, pairing code, and global API key are not forwarded. Event logging and terminal QR logging are redacted. The original reconnect/session policy, including 408 handling, is unchanged.

The overlay adds `Chatwoot.inboxId` to all three Prisma provider schemas and adds PostgreSQL/MySQL migrations; the image's `runWithProvider.js` maps `psql_bouncer` to PostgreSQL migrations. The image's existing startup migration and Prisma generation step applies them before serving. New NEXI instances require the stable ID; legacy instances without one retain their existing name lookup. For NEXI, manual rename or a later duplicate friendly name cannot redirect inbound or outbound transport. `nameInbox` remains descriptive. **IMAGE DIGEST PINNING REMAINS A DEPLOYMENT PREREQUISITE.**

`node --test *.test.cjs` exercises authentication, the shared Redis command contract, replay after a new ledger client, concurrent claims, instance isolation, stable Inbox ID, and event signing. The bundle and Prisma patches were applied to the inspected image/source files and syntax checked. A live Redis, Docker build, database migration, and end-to-end delivery remain deployment validation; no infrastructure was installed here.
